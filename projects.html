01 · Diagnosis

Find the first
wrong turn.

  • Research system
  • CLIP + sequence models
  • Bayesian fusion
  • Interval DP

A long trajectory can end with an obvious error while the action that caused it is much earlier. SynTriageGUI treats that ambiguity as a decision problem: estimate risk, then spend human attention where it reduces uncertainty most.

Problem

Terminal failure hides the origin.

Errors accumulate through a GUI task. Reviewing every step is expensive, while trusting the final exception often identifies a symptom rather than the earliest faulty action.

Method

Turn a trajectory into evidence.

The framework combines model confidence, historical action success, and evidence from similar traces. Human review is scheduled over candidate intervals, not blindly over the full sequence.

Engineering

Make experiments reproducible.

  • Built before/after screenshot, action, control, and screen-change features with frozen CLIP representations and caching.
  • Trained pointer-probability, discrete-risk, and monotonic change-point models with a no-root class and interval soft labels.
  • Implemented feedback-weighted online updates after human confirmation or automatic repair.

Multimodal sequence evidence

Screenshots, actions, UI controls, and page changes become step-level inputs for root-cause models trained under one reproducible evaluation path.

Budget-aware human inspection

Bayesian evidence fusion feeds an interval dynamic program that selects the next human check, narrowing the candidate range without reviewing every step.

Feedback that changes the next decision

Confirmations and repairs update action reliability online, with feedback-source weighting so later diagnoses reflect what was learned during the current task.

02 · Generation

Keep the long
job moving.

  • AI product
  • LangGraph
  • PostgreSQL + Redis
  • FFmpeg

VidForge turns product assets into scripts and finished videos. The difficult part is not one model call; it is keeping the multi-stage job observable, retryable, and useful when an individual shot or dependency fails.

Problem

Long tasks break the request model.

Inference and transcoding outlast a normal request. A single failure near the end of a workflow should not erase the useful shots, state, and progress that already exist.

Workflow

Generate, judge, then route again.

A LangGraph state graph connects asset understanding, script generation, video synthesis, and quality evaluation. Weak outputs enter regeneration branches, with feedback returned to upstream nodes.

Reliability

Progress must survive failure.

  • Persisted job state in PostgreSQL and streamed progress over WebSocket.
  • Split divergent workloads across Redis/BullMQ queues with priority, retries, monitoring, and a Redis-unavailable degradation path.
  • Stored per-shot execution state and allowed complete shots or fallback fragments to survive partial failures.
Workflow instrument stateful generation / 04 stages
Ground the generation

Product assets and selling points are combined with retrieved scripts, product knowledge, and high-scoring results to keep the model close to the brand and category.

Make the sequence inspectable

A stateful graph turns product context into a storyboard and per-shot generation tasks, so progress can be traced at a finer granularity than the finished video.

Queue the expensive work

Inference, shot generation, composition, and transcoding run in separate queues. FFmpeg handles format adaptation, voice, music, subtitles, and stitching while persisted state makes retries possible.

Close the loop

Quality results decide whether to accept, regenerate, or return feedback upstream. If assembly fails, completed fragments remain available for a degraded output.
